## Инженерный подход

```text
РАЗБОР ПРОЦЕССА  →  ТЗ И ПРАВИЛА  →  РАБОЧИЕ ЭТАПЫ  →  ПРОВЕРКИ  →  ЗАПУСК И ПОДДЕРЖКА
```

Критичные правила — пересечения записей, цены, предоплаты, права и денежные операции — проектирую так, чтобы их проверяла сама система, а не память сотрудника. Для реальных процессов использую ограничения базы данных, миграции, фоновые задачи, тесты и журналирование изменений.
